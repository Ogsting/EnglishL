# 词库更新（B 方案）与静态托管

## 1. 静态托管是什么

**静态托管 = 只放文件、不跑后端代码的网站空间。**

你上传什么文件，别人打开网址就拿到什么文件：HTML、JS、CSS、JSON、图片。
它不会执行你上传的 PHP/Java/Python，也不会有数据库 —— 对你这个 App 来说**完全够用**，
因为 App 本身就是一堆静态文件（`dist/` 里的东西），查词、背单词、段位计算全在手机本地跑。

| 是静态托管 | 不是静态托管 |
|---|---|
| GitHub Pages、jsDelivr、Vercel、Netlify、Gitee Pages | 阿里云 ECS、自己架 Nginx（虽然也能放静态文件，但你要自己运维） |
| 对象存储 OSS/COS 开"静态网站" | 需要登录、数据库、接口的后端服务 |

对「联网增量更新」来说，静态托管只需要放 **2 个 JSON 文件**：

```
words/version.json     { "latest": 2 }
words/patch-2.json     只包含 v1 → v2 的变化（几 KB）
```

## 2. 要不要申请？GitHub Pages 是免费自带的

- **GitHub Pages 不需要申请、不需要审核、不需要备案**。有 GitHub 账号 → 建一个仓库 → 设置里点两下就有了。
- 它是"每个仓库附赠一个静态网站"，所以你可以把它当免费网盘 + 免费域名用。
- 国内访问 `*.github.io` 有时不稳，但**词库更新失败会自动跳过**，不影响 App 使用；也可以用 jsDelivr 加速（见下）。

## 3. 怎么看到自己的 GitHub Pages 地址

1. 建仓库（Public），把 `dist/` 或 `words/` 传上去
2. 仓库 → **Settings** → 左侧 **Pages**
3. Build and deployment → Source 选 **Deploy from a branch** → Branch 选 `main` / `/ (root)` → **Save**
4. 等 1 分钟刷新，页面顶部会出现：
   > Your site is live at `https://你的用户名.github.io/仓库名/`
5. 这个地址就是你的静态托管地址。放 `words/version.json` 就能访问
   `https://你的用户名.github.io/仓库名/words/version.json`

**更省事的替代：jsDelivr**（直接读 GitHub 仓库，国内通常更快，自带 CDN 和 CORS）

```
https://cdn.jsdelivr.net/gh/你的用户名/仓库名@main/words/version.json
```

不用开 Pages，文件推上去就有；以后更新文件 URL 不变。

## 4. 发布一版新词库的完整流程

```bash
# 1. 改完词库后重新生成
python tools/build_words.py                # -> src/data/words.json

# 2. 和上一版对比，生成补丁（旧版别删，留着当基线）
python tools/make_patch.py old/words.json src/data/words.json --version 2 --out words/patch-2.json

# 3. 上传 words/patch-2.json，然后把 version.json 改成 {"latest": 2}
```

用户端：下次打开 App（有网）→ 读到 `latest: 2`、本地是 1 → 拉 `patch-2.json` → 合并 → 记下 v2。
整个过程静默，断网自动跳过。

## 5. App 里怎么开

`src/config.ts`：

```ts
export const WORD_BASE = 'https://cdn.jsdelivr.net/gh/你的用户名/englishl@main/words'
```

留空 = 关闭联网更新（默认就是这个状态，不影响离线使用）。
也可以在构建时注入：`VITE_WORD_BASE=... npm run build`。

调试时可以用地址参数临时指定源：`http://127.0.0.1:5173/?wordbase=/mock`
（`public/mock/` 里已经放了一份可用的示例补丁，改一下就能测）。
