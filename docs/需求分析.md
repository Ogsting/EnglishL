# 四六级单词卡 App — 需求分析（v0.1 草案）

> 待与用户确认后升级为 v1.0 开发规格。

## 0. 已确认决策（2026-XX 第一轮确认）

| 编号 | 问题 | 用户决策 |
|---|---|---|
| D1 | 交付形态 | **PWA + Android APK 两者都要**（先 PWA，Capacitor 打包 APK） |
| D2 | 错题定义 | **A：左滑即记为错**，进错题本；同时引入简化艾宾浩斯权重（错词权重大、更早复现；答对的词也会按间隔再次出现） |
| D3 | 错题本视觉 | 错误次数越多，卡片**材质越深/越稀有**，且该梯度**由主题包提供**（MC：橡木→丛林原木→深色橡木→绯红木→下界合金） |
| D4 | 每日达标线 | **每天 50 个"右滑认识"的单词**；未达标或未打开 → **−1 小段位（= 少一颗煤炭）** |
| D5 | 词库 | **内置离线词表 + 联网增量更新** |
| D6 | 段位映射 | 待确认，见 [段位与主题设计.md](段位与主题设计.md) |


## 1. 需求还原（把原始描述的编号理顺）

| # | 原始描述 | 还原后的功能点 |
|---|---|---|
| R1 | 断网执行 | 完全离线可用：词库、进度、段位、错题全部本地存储，无网不降级 |
| R2 | 联网搜索所有 4/6 级单词并添加到词库 | 在线获取 CET-4 / CET-6 全量词表 → 落地为本地词库；后续可增量更新 |
| R3 | 底部导航 bar：home / own / wrong | 三个 Tab：首页、个人单词本、错题本 |
| R4 | 首页：记录全部 4/6 级单词，左滑不熟、右滑熟悉，正反面中英随机约 50%，滑后显示正确释义 | 卡片流 + 熟悉度记录 + 随机展示面 + 翻面释义 |
| R5 | 个人单词本：可添加自己想学的单词，除"用户自加"外与首页一致 | 第二个词库（用户自建），独立进度，交互同首页 |
| R6 | wrong：把所有"做错"的题加入错题本，格式左中文右单词，滑动两次删除 | 错题收集 + 复习视图 + 二次滑动确认删除 |
| R7 | 奖惩：每天复习足够单词升一小段，反之降一小段；10 小段 = 1 大段，10 大段 = 1 大大段 | 每日目标判定 + 段位状态机（100 级） |
| R8 | 主题设置模块：如「我的世界」主题，段位变为煤炭/铜/铁/金/钻石/下界合金，并配 MC 风 UI | 可插拔主题包：配色、字体、素材、段位名词表、音效 |

## 2. 需求中的矛盾与缺口（必须澄清才能开工）

### G1 「做错」在纯滑动交互里不存在（最高优先级）
R4 只有"熟悉 / 不熟悉"两个动作，没有对错判定；但 R6 要求"把所有功能做错的错题"进错题本。
候选定义：
- **A. 左滑即记为错**：最省事，不熟 = 错，直接进错题本（顺带覆盖 R6，无需额外 UI）。
- **B. 增加"释义自测"环节**：翻面后给 2~4 个中文释义选项，选错才算错。
- **C. A + B 并存**：左滑进错题本；自测答错进错题本并提高权重。
- **D. 用户手动"加入错题本"**。
> 影响：错题本的数据来源、首页卡片是否必须翻面、R7 的"复习量"如何计数。

### G2 离线 vs 在线（R1 与 R2 冲突）
"断网执行" + "联网搜索词库" 不能同时是一次性行为。建议：**词库随安装包内置（离线首选），联网仅用于增量更新**。
需要确认：是否接受内置词表？首次启动若断网是否必须可用？（推荐：是）

### G3 「显示英文或中文随机约 50%」
需要定义随机粒度：
- 每张卡独立掷硬币（长期自然≈50%，短期可能连续同向）；
- 或一轮内强制均衡（交替/洗牌保证 50/50）。
> 推荐：每张卡独立 50%，并在统计里记录方向偏差，避免一边倒地只练中→英。

### G4 「记录全部 4/6 级单词」的呈现逻辑
- 顺序（字母序 / 词频序 / 随机）？
- 走完一轮后熟悉词是否还出现？是否引入间隔重复（SRS，如 SM-2 简化版）？
- "记录"是记录熟悉度（新词/模糊/熟悉），还是只记录已学？
> 推荐：默认"未学 → 学习中 → 已熟悉"三态 + 简化 SRS（熟悉词拉长间隔），否则滑动手势没有长期价值。

### G5 段位规则细节（R7）
- 每日达标线是多少词？（50 / 100 / 自定义）
- 未达标降 1 小段；**完全没打开 App 的那天**是否也降？
- 超额完成是否只升 1 段，还是可连升？
- 到最高段（100 级）后如何处理？降到最低后是否保底？
- 跨天以本地时间几点为界（0 点 / 4 点）？
- 是否允许关闭/宽松模式（学生反感惩罚）？

### G6 MC 主题的段位映射装不下 100 级（R8 的真实设计问题）
"煤炭→铜→铁→金→钻石→下界合金"只有 6 个名词，而层级是 10×10=100。
需要选一种映射：
- **M1**：大大段位 = 材料（6 个，可扩展木/石/黑曜石/基岩…），大段位 = 材料内阶段名，小段位 = I~X；
- **M2**：材料 = 大段位（10 个材料名），小段位 = I~X，大大段位另起名（如 主世界/下界/末地）；
- **M3**：材料只做视觉皮肤，段位文字仍用"Ⅳ-金"这类组合显示。

### G7 主题系统的边界
主题包要不要包含：段位名词表、配色、字体（像素字体）、图标/背景素材、音效、升级动画？
素材来源：**不能直接抠 MC 游戏贴图（版权）**，只能自绘像素风 / 用户自备素材。

### G8 错题本的"两次滑动"
- 同卡左滑两次（第二次确认）？
- 还是左滑一次 = 标记删除，再滑一次 = 确认，中间显示"再滑一次删除"？
- 删除是否可撤销（toast 撤销 / 回收站）？
- 错题复习答对后是否自动移出？

### G9 「个人单词本」与主词库的关系
用户自加的词：是否也进错题本？是否计入段位目标？是否与 CET 词去重（重复添加怎么办）？是否支持例句/自定义释义？

### G10 卡片交互的细节
滑后"显示正确单词意思"是：翻面后停留（需再点一下继续）还是自动滑出下一张？停留多久？是否支持撤销上一张？

### G11 未覆盖但值得确认
- 发音：是否要音标 / 点击朗读（离线 TTS 或音频包）？
- 数据备份：纯离线意味着换机/重装即丢，是否要 JSON 导入导出？
- 账户 / 同步 / 多设备：是否需要？
- 界面语言：全中文？是否中英双语？
- 每日学习量、连续打卡、升级弹窗、音效等游戏化元素要多少？
- 深色模式、平板适配、无障碍？

## 3. 建议的技术方案（基于本机环境）

本机：Node/npm、Java 21、Android Studio + Android SDK、HBuilderX；**无 Flutter**。

| 方案 | 优点 | 代价 |
|---|---|---|
| **A. PWA（Vue/React + Vite + IndexedDB + Service Worker）** | 立刻能在手机浏览器跑，离线可靠；后续可用 Capacitor 直接打 APK；开发最快 | 需要"添加到主屏幕"，iOS 能力略弱 |
| **B. Android 原生（Kotlin + Room）** | 真·APK，手感最好，离线最稳 | 开发量大，UI 迭代慢，我在此环境难以跑模拟器验证 |
| **C. uni-app / HBuilderX** | 本机已有 IDE，一套代码多端 | 依赖 IDE 生态，调试链路不如 A 透明 |
| **D. Flutter** | 跨端体验好 | 需先下载安装 Flutter SDK（约 1GB+） |

> 建议：**A 起步（先看到可用界面）→ 需要 APK 时用 Capacitor 打包**。若你明确只要 Android 安装包，直接选 B 或 A+Capacitor。
